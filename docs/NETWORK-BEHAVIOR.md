# 网络检测与登录规则

macOS 与 Windows 分别处理网络记忆和当前请求出口。网络记忆只保存实际认证网络的网关、子网等派生特征，TUN、附加网卡和连接组合不作为持久身份。

候选来自两次一致的系统快照，分别核验物理默认路由（含可绑定的 scoped 默认）、源地址和关联 DNS。优先选择已记住的系统主物理网络，再选择其他已记住的活动候选；一条网络的记忆不能授权另一条出口。

应用模型将候选的网络描述和绑定信息一并传给认证客户端。探测、发现及发送前后均重新核对，不能自行改用其他出口。

## 请求

| 目的 | 地址或范围 |
| --- | --- |
| 基础联网探针 | `https://www.apple.com/library/test/success.html`、`http://www.msftconnecttest.com/connecttest.txt` |
| 校园身份确认 | `https://net.szu.edu.cn/srun_portal_pc` |
| 教学／办公区认证 | `https://net.szu.edu.cn/cgi-bin/get_challenge` 与 `/cgi-bin/srun_portal` |
| 宿舍门户与认证 | `http://172.30.255.42:801/eportal` 与 `/eportal/portal/login` |
| 常用网址检查 | 用户明确启用的 HTTP／HTTPS 地址 |
| 兼容诊断 | 校园认证首页及基础探针，对比直连和系统代理路径 |

基础联网检测要求 HTTP 200 及固定的预期正文：

- 快速检测：任一基础项通过即停止等待，跳过自选网址。
- 完整检测：等待 Apple、Microsoft 及当次启用的网址，全部通过才判为完整通过。

macOS 快速检测遇到严格白名单内的校园登录跳转时，也停止等待另一项，但结果仍为未联网。跳转不能证明校园身份或授予认证权限。基础项核验正文，自选网址只检查响应头，两者范围不同。

基础检测和校园请求绕过系统 HTTP/HTTPS 代理配置。活动 TUN 路由下，两端使用绑定已核验物理接口及源 IPv4 的通道，通过关联 DHCP／服务 DNS 解析，不使用全局 Fake-IP。出口不明或绑定失败时停止请求。

已记住网络的物理通道在 TUN 开关前后保持绑定。常用网址和未绑定的兼容诊断使用各平台传输；Windows 固定认证请求不回退到未知出口。边界与 IPv4 限制见[物理通道](CAMPUS-PHYSICAL-CHANNEL.md)。

认证请求不跟随跳转，限制超时及响应大小。Cookie 仅在当次认证会话内使用，不写入磁盘。TLS 异常、意外跳转或协议冲突均触发保护。

## 认证提交

手动登录由用户点击触发，并先重新检测。只有新结果仍显示需要恢复连接时才继续；已恢复联网或只剩网站业务错误时不提交。强制重新登录需另行确认，默认取消。

开启自动重连后，自动登录还需已保存账号、连接持续异常、适用校园服务已核验，并满足网络资格、暂停及冷却条件。基础部分失败或严格校园门户跳转可进入两轮确认和一次恢复；稳定网络的第二轮通常在 5 秒后进行。

两项基础均通过时，自选网址的普通超时、DNS 或连接错误只更新诊断，不触发自动校园认证。每轮最多一次正式提交，提交后复检不再次提交。

### 换网后的优先恢复

真实换网后，两端提供 45 秒优先恢复窗口：

1. 已保存账号、开启自动重连，且无暂停、冷却或不明提交保护时，立即开始基础快速检测。
2. 首次失败后 1 秒再次确认。两次失败仍须通过当次校园核验和信任资格检查，才能认证。
3. 尚未提交时，暂时失败可在窗口内每 3 秒复查；窗口结束后采用常规退避间隔。
4. 此阶段不等待常用网址。恢复后如偏好完整检测，2 秒后补查；基础通过不标为所有网址通过。

### 恢复条件与保护

恢复信号包括明确的连接错误、DNS 失败、超时及严格匹配固定校园门户首页的跳转。校园跳转只保留内存标记，不跟随、不保存原 Location，也不替代校园身份核验。

401、403 等业务回复、TLS／安全策略错误、无效输入、取消及缺失结果不能单独触发恢复。代理或隧道存在本身不否决恢复，也不证明故障原因。

两端已绑定通道的自动恢复及登录后复检优先核验两项基础结果。基础未全部通过时不等待常用网址；偏好完整检测时再补查网址，未查项目保持未检测状态。

每个部分连接异常阶段只允许一轮自动恢复。重新开放恢复次数前，连续两轮完整检测须同时满足：

- Apple、Microsoft 均通过。
- 所有启用的项目都有 HTTP 回复，且没有校园门户跳转。

HTTP 403 计入有回复，总体仍显示部分通过。持续连接失败、结果缺失、取消或配置变化不重置次数限制；该限制与认证保护分别处理。

错误密码、结果不明和安全异常均有暂停规则。结果未知不能视为未提交。

已绑定物理通道的一轮完整基础检测中，Apple、Microsoft 均通过即可解除结果不明保护；常用网址另行补查，未查项目不算通过。未绑定传输仍须核验完整范围。此过程不解除用户暂停、密码或安全保护，也不缩短 90 秒冷却。

教学记忆只保存教学服务证明，仅有这类资格时，自动选区使用教学 HTTPS 流程，不取得宿舍自动认证资格。教学自动认证仍需当次校园核验。

宿舍记忆须同时保存教学及宿舍证明；多个物理出口或网络隧道下需要更强的当次证明。SSID、显示名称或单个网页响应不能代替校园网络核验。

### 重复提交与物理链路切换

90 秒冷却用于防止重复认证，不限制只读探针或手动立即检测。认证明确成功且当前绑定通道的 Apple、Microsoft 均通过后，才在内存标记该物理接口的成功范围。

另一条物理接口重新通过校园服务、网络资格及当前操作核验后，可使用独立截止时间。切回旧接口仍检查原截止时间，A → B → A 不重置冷却。

隧道、默认路由、地址或名称变化不建立新的物理接口资格。失败、结果不明、提交后取消及从磁盘恢复的冷却均全局生效，不恢复独立接口的冷却豁免。

联网成功不清除用户暂停、密码或安全保护。已在线时显示联网结果，不将未结束的防重复冷却显示为等待登录生效。

## 网络记忆与找网

会话信任只在内存，换网、休眠或退出后撤销。持久网络记忆使用派生特征，标签文件独立保存显示名称和 SSID。网络记忆不直接产生会话信任。

两端只恢复用户选定的已记住校园 Wi-Fi。自动找网与允许开启电源分别控制，新用户默认均关闭。应用不读取无线密码，不导入系统保存的全部 Wi-Fi，也不抢占已有物理连接。

Windows 自动关联使用临时开放配置，名称取实际 SSID，SSID XML 与名称字段分别转义。名称只用于显示和连接，不授予认证资格，不改接入点名称，也不批量删除旧配置。

## 常用网址

最多启用 12 项，建议日常不超过 3 项。地址不能包含用户信息、查询参数或片段。请求不带 Cookie、凭据或客户端证书，不跟随跳转。

检测收到 HTTP 响应头即停止，结果只表示此次 HTTP 响应。网页正文、JavaScript、登录、聊天、WebSocket 及后台 API 均不在检测范围内；2xx 不代表完整页面或功能正常。

403、身份验证挑战、跳转、超时及 DNS/TLS 错误需按各自原因排查，不能单凭这些结果判断校园网掉线。

每轮结果在内存中保留当次连接策略和详情，修改设置不改变已有结果。具体网址不进入检测历史或诊断导出。

检测历史不保存当次网址策略；诊断摘要显示的当前设置不能作为历史路径证据。通过比例包含当次所选项目的样本结果，不代表校园链路持续在线率或真实带宽。

| 连接选项 | 请求方式 |
| --- | --- |
| 使用系统设置 | 使用适用的系统代理、自动代理规则（PAC）及例外规则；实际是否走代理取决于对应规则，选项本身不说明具体节点 |
| 绕过系统代理 | 绕过系统 HTTP/HTTPS 代理配置，仍使用系统 DNS 和路由 |

macOS 通过 URLSession 使用系统配置，Windows 由 WinHTTP 的自动代理模式读取适用配置。浏览器可能另有扩展或独立代理、缓存、登录 Cookie、DNS／IPv4／IPv6 路径及页面脚本使用的 API，结果可能不同。

VPN/TUN 的全局路由、按应用或目的地址分流可能改变检测路径；IPv4／IPv6、DNS／Fake-IP、代理节点及隧道重连也可能影响结果。隧道存在、网址有响应和需要校园认证分别判断，不能单凭其中一项定位故障或节点。

## 系统配置

应用读取网络及代理状态，提供诊断和可复制的建议规则，不修改 VPN、代理、DNS 或路由。读取失败时显示“未知”。

排查时先看结果中所用的连接方式及错误，再核对分流、节点和 DNS，并在浏览器验证所需功能。校园登录只处理校园认证，代理或网站问题需另行处理。

## 实现与参考

macOS 合并同一同步代码段内重复的完整物理租约采集。异步前后、物理 DNS／套接字绑定及 HTTP 发送前仍重新核验，不以时间缓存替代发送前检查。

- [URLSession 代理](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/connectionproxydictionary)：未覆盖代理配置时采用系统设置。
- [Apple VPN 路由](https://developer.apple.com/documentation/networkextension/routing-your-vpn-network-traffic)：路由、全量隧道和按应用规则可改变连接路径。
- [WinHTTP 代理](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpopen)：自动代理模式采用适用的系统和用户配置。
- [Chrome 代理](https://developer.chrome.com/docs/extensions/reference/api/proxy)：扩展可使用系统、PAC、固定代理或直连设置。
