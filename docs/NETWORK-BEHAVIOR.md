# 网络检测与登录规则

macOS 与 Windows 分别处理网络记忆和当前请求出口。网络记忆只保存实际认证网络的网关、子网等派生特征，TUN、附加网卡和连接组合不作为持久身份。

候选来自两次一致的系统快照，分别核验物理默认路由（含可绑定的 scoped 默认）、源地址和关联 DNS。一条网络的记忆不能授权另一条出口。

两端优先观察可靠的系统主物理候选，再考虑已记住的活动候选及原有确定性候选，不单凭网卡类型切换。未记住的主连接也可独立检测、核验并由用户记住，不沿用次要 Wi-Fi 的在线结果或认证资格。

单条网卡记录异常时，只排除该候选。静态 IPv4 配置使用该网卡的源地址、网关、子网和关联 DNS 核验，不要求存在 DHCP 记录。候选诊断仅记录固定原因和数量，不包含网卡名称或地址。

应用模型将候选的网络描述和绑定信息一并传给认证客户端。探测、发现及发送前后均重新核对，不能自行改用其他出口。

普通检测或入口发现期间，可以交接到新的可靠主物理连接，不要求它已被记住。手动登录前重新读取当前连接，避免系统通知延迟时继续使用旧信息。凭据预检、提交及确认阶段保持原连接，从全部有效候选核对，不因旧连接未进入记忆而改道。

旧连接失效时取消操作，不借换网重复提交；已提交而无法确认的结果仍按可能到达服务器处理。旧连接的联网结果、服务证明和恢复资格不转移到新连接。

## 请求

| 目的 | 地址或范围 |
| --- | --- |
| 基础联网探针 | `https://www.apple.com/library/test/success.html`、`http://www.msftconnecttest.com/connecttest.txt` |
| 校园身份确认 | `https://net.szu.edu.cn/srun_portal_pc` |
| 教学／办公区认证 | `https://net.szu.edu.cn/cgi-bin/get_challenge` 与 `/cgi-bin/srun_portal` |
| 宿舍门户与认证 | `http://172.30.255.42:801/eportal` 与 `/eportal/portal/login` |
| 常用网址检查 | 用户明确启用的 HTTP／HTTPS 地址 |
| 兼容诊断 | 校园认证首页及基础探针，对比直连和系统代理路径 |

基础联网检测要求 HTTP 200 及固定的预期正文：

- 快速检测：任一基础项通过即停止等待，跳过自选网址。
- 完整检测：等待 Apple、Microsoft 及当次启用的网址，全部通过才判为完整通过。

快速检测遇到严格匹配的校园登录首页跳转时，也停止等待另一项，但结果仍为未联网。跳转不能证明校园身份或授予认证权限。基础项核验正文，自选网址只检查响应头，两者范围不同。

基础检测和校园请求绕过系统 HTTP/HTTPS 代理配置。活动 TUN 路由下，两端使用绑定已核验物理接口及源 IPv4 的通道，优先通过关联 DHCP／服务 DNS 解析，不使用全局 Fake-IP。两端可为三个固定域名尝试受限 HTTPS 备用解析；仍绑定原出口并核验证书，不能用地址候选授信。出口不明或绑定失败时停止请求。[解析范围与缓存限制](CAMPUS-PHYSICAL-CHANNEL.md)

已记住网络的物理通道在 TUN 开关前后保持绑定。常用网址和未绑定的兼容诊断使用各平台传输；Windows 固定认证请求不回退到未知出口。边界与 IPv4 限制见[物理通道](CAMPUS-PHYSICAL-CHANNEL.md)。

认证请求不跟随跳转，限制超时及响应大小。Cookie 仅在当次认证会话内使用，不写入磁盘。TLS 异常、意外跳转或协议冲突均触发保护。

## 认证提交

手动登录由用户点击触发，并先重新检测。只有新结果仍显示需要恢复连接时才继续；已恢复联网或只剩网站业务错误时不提交。强制重新登录需另行确认，默认取消。

开启自动重连后，自动登录还需已保存账号、连接持续异常、适用校园服务已核验，并满足网络资格、暂停及冷却条件。

Windows 的校园物理通道连续两次基础检测失败时，可进入恢复。一项仍通过时，需要固定探针明确跳到登录页，再独立确认；单个网站超时不会触发自动认证。登录成功页只能提供入口信息。Mac 的部分失败判定见[平台差异](PLATFORM-DIFFERENCES.md)。

Windows 已记住网络且可自动恢复时，普通监测间隔最长 15 秒；快速模式也定期复查两个基础地址。明确登录页跳转的第二次确认在 1 秒后安排。按流量计费、暂停、失败退避及 90 秒认证保护继续生效；这些间隔不包含请求耗时。

常用网址只作额外检测。校园直连的两项基础检测连续恢复后，即可继续监测下一次校园掉线；不必等所有自选网址恢复。单个网址失败不会触发登录，基础检测尚未恢复时也不会重置本轮恢复限制。

正式登录请求尚未发送时，准备阶段的暂时故障会继续重试，间隔从 5 秒逐步延长至 5 分钟。按流量计费的连接采用较长间隔。

每次重试仍检查当前连接、网络记忆及校园服务。密码错误、TLS 异常、取消、结果不明和已提交认证的保护保持原规则。

网线保持连接而校园登录会话失效时，也由自动重连处理。此流程与 Wi-Fi 找网开关、SSID 和定位权限无关；教学与宿舍首页同时可访问，不能据此判断所在区域或认证入口。

两项基础均通过时，自选网址的普通超时、DNS 或连接错误只更新诊断，不触发自动校园认证。每轮最多一次正式提交，提交后复检不再次提交。

### 换网后的优先恢复

真实换网后，两端提供 45 秒优先恢复窗口：

1. 已保存账号、开启自动重连，且无暂停、冷却或不明提交保护时，立即开始基础快速检测。
2. 首次失败后 1 秒再次确认。两次失败仍须通过当次校园核验和信任资格检查，才能认证。
3. 尚未提交时，暂时失败可在窗口内每 3 秒复查；窗口结束后采用常规退避间隔。
4. 此阶段不等待常用网址。恢复后如偏好完整检测，2 秒后补查；基础通过不标为所有网址通过。

### 恢复条件与保护

恢复信号包括明确的连接错误、DNS 失败、超时及严格匹配固定校园门户首页的跳转。校园跳转只保留内存枚举，不跟随、不保存原 Location 或查询参数，也不替代校园身份核验。

401、403 等业务回复、TLS／安全策略错误、无效输入、取消及缺失结果不能单独触发恢复。代理或隧道存在本身不否决恢复，也不证明故障原因。

两端已绑定通道的自动恢复及登录后复检优先核验两项基础结果。基础未全部通过时不等待常用网址；偏好完整检测时再补查网址，未查项目保持未检测状态。

每个部分连接异常阶段只允许一轮自动恢复。重新开放恢复次数前，连续两轮完整检测须同时满足：

- Apple、Microsoft 均通过。
- 所有启用的项目都有 HTTP 回复，且没有校园门户跳转。

HTTP 403 计入有回复，总体仍显示部分通过。持续连接失败、结果缺失、取消或配置变化不重置次数限制；该限制与认证保护分别处理。

错误密码、结果不明和安全异常均有暂停规则。结果未知不能视为未提交。

已绑定物理通道的一轮完整基础检测中，Apple、Microsoft 均通过即可解除结果不明保护；常用网址另行补查，未查项目不算通过。未绑定传输仍须核验完整范围。此过程不解除用户暂停、密码或安全保护，也不缩短 90 秒冷却。

仅有教学服务证明的记忆不提供宿舍自动认证资格。当前需要宿舍认证时，须补充相应资格；教学自动认证也须通过当次校园核验。

两端自动选区会参考本轮、同一物理绑定的基础探针跳转，区分教学与宿舍候选。只保留教学／宿舍枚举，严格检查协议、主机、端口、路径和编码。跳转仍须配合独立校园 HTTPS 身份、适用服务、网络记忆或本次信任；系统路径列、常用网址和网络名称不提供选区依据。

已明确选择的入口优先。自动选择时先参考当轮物理探针，线索冲突时不提交。没有跳转线索时，若固定 HTTPS 首页返回的 SRun 配置与本轮绑定源地址一致，可选择教学入口；其次考虑已记住的教学入口。两种主页均可访问却没有候选时，提示选择登录区域，不默认提交宿舍认证。这里的区域指登录方式，不代表电脑所在地点。

配置只用于本轮候选选择，不代表已登录，也不代替网络资格或暂停检查。正式认证前重新读取固定首页，核对控制器、配置与 challenge 的源地址；不保存这些原始信息，不按网线或 Wi-Fi 写死控制器。

两端的 CONFIG 候选仅接受固定 TLS 页面中唯一、受支持的内联字面量。解析保留脚本原文字节，区分属性、注释与惰性内容，拒绝重复键、畸形值和可识别的 CONFIG 改写或动态全局访问。解析器不执行 JavaScript，不读取外部脚本，也不保证浏览器执行后的配置状态。普通外部脚本资源和无关页面属性可以保留。

Windows 要求数字连续完整，无引号数字属性键不超过 JavaScript 安全整数范围。解析区分 HTML 属性、注释、DOCTYPE 与 SVG／MathML 上下文；遇到脚本双重转义、frameset、追溯超限或不支持的内联正则／除法语法时，不提供新的 CONFIG 候选。显式入口、历史记忆和严格跳转流程仍沿用各自检查。

两端可将固定校园域名上已知的电脑、手机、成功展示页和入口页跳转识别为教学候选，包括 HTTP 80 与 HTTPS 443；不跟随跳转，不保留查询参数，也不据此判定设备类型、校园身份或登录成功。实际教学认证仍仅访问固定 HTTPS 接口，控制器参数从本轮固定首页读取，不按设备写死为某个值。

依据跳转选定教学入口后，预检失败或未取得 challenge 也不会试投宿舍入口。网络记忆中的入口不代表所在地点；只有明确接受的认证结果才更新已有记忆的入口选择，服务主页可达只刷新原有记录，不改选区或证明范围。

教学认证更新入口偏好时，保留网络 ID、特征及证明标志。未重新核验宿舍服务时，不延长历史宿舍证明的有效期；历史入口偏好不能覆盖相冲突的当前物理线索。失败暂停按用户原始选择确定范围，不按本轮派生入口改变。更改区域不解除结果不明、密码错误或安全暂停。

“核验校园服务”只重新检查已记住网络的服务，可随时取消。它不登录、不改记忆范围或有效期，不解除暂停和冷却，也不提前安排自动认证。双入口提示只采用当前连接的有效核验结果。

自动重连模式下，已记住的网络重新接入并通过基础检测后，两端会自动核验当前校园服务，并显示核验中、已确认或未确认。

同一连接核验成功后不逐轮重复；距成功完成约 15 分钟后，随原监测节奏刷新。两端使用单调时钟计算截止，不受系统时间跳变影响。失败后仍按原监测节奏重试，距核验结束至少 30 秒，并非每 30 秒固定发起请求。

此步骤不提交账号密码，不新增网络记忆或信任；真正需要恢复登录时，仍重新核验适用服务。自动重连模式下，手动检测同一已记住网络也会补齐这项确认；手动检测模式、定时检测模式和只读模式不新增自动核验。

宿舍记忆须同时保存教学及宿舍证明；多个物理出口或网络隧道下需要更强的当次证明。SSID、显示名称或单个网页响应不能代替校园网络核验。

### 重复提交与物理链路切换

90 秒冷却用于防止重复认证，不限制只读探针或手动立即检测。认证明确成功且当前绑定通道的 Apple、Microsoft 均通过后，才在内存标记该物理接口的成功范围。

另一条物理接口重新通过校园服务、网络资格及当前操作核验后，可使用独立截止时间。切回旧接口仍检查原截止时间，A → B → A 不重置冷却。

隧道、默认路由、地址或名称变化不建立新的物理接口资格。失败、结果不明、提交后取消及从磁盘恢复的冷却均全局生效，不恢复独立接口的冷却豁免。

联网成功不清除用户暂停、密码或安全保护。已在线时显示联网结果，不将未结束的防重复冷却显示为等待登录生效。

## 网络记忆与找网

会话信任只在内存，换网、休眠或退出后撤销。持久网络记忆使用派生特征，标签文件独立保存显示名称和 SSID。网络记忆不直接产生会话信任。

首次设置绑定物理网线时，须实际核验并记住当前网络；选择教学／办公区入口不计为已完成网络记忆。自动重连负责校园认证，Wi-Fi 找网只是可选的无线连接功能。

已有教学记忆但本轮需要宿舍认证时，保留原记录，提供核验并记住、本次信任和忘记网络。仅本次信任不会完成永久记忆设置；写入成功后才更新设置进度。界面按本轮所需服务显示核验状态，教学身份通过不等于宿舍服务已通过。

两端只恢复用户选定的已记住校园 Wi-Fi。自动找网与允许开启电源分别控制，新用户默认均关闭。应用不读取无线密码，不导入系统保存的全部 Wi-Fi，也不抢占已有物理连接。

macOS 对暂未找到目标、短暂连接失败采用 2 秒起的递增退避，上限 5 分钟；权限不足、无线网卡不可用、需要系统连接或链路不明仍保留较保守的等待。退避从本次尝试结束计时，不包含系统扫描耗时。无线电源发生实际变化时，重新读取本地状态并唤醒旧等待；重复状态不重置退避，进行中的扫描不重叠。找回 Wi-Fi 后先等待物理网络信息，再按原规则核验校园服务与恢复会话。

macOS 收到扫描设备忙时，不对每个目标重复扫描，只从系统已有扫描结果精确挑选已选的开放网络。仅因设备忙而无法继续时，退避最长 15 秒。扫描结果只用于无线接入，不提供校园身份或信任；不读取无线密码或修改系统无线配置。

Windows 优先使用所选 Wi-Fi 已保存的系统连接，不读取密码或改写配置；没有已保存连接时，仅尝试开放网络，使用临时配置并分别转义 SSID XML 与名称字段。名称只用于显示和连接，不授予认证资格，不改接入点名称，也不批量删除旧配置。

## 常用网址

最多启用 12 项，建议日常不超过 3 项。地址不能包含用户信息、查询参数或片段。请求不带 Cookie、凭据或客户端证书，不跟随跳转。

检测收到 HTTP 响应头即停止，结果只表示此次 HTTP 响应。网页正文、JavaScript、登录、聊天、WebSocket 及后台 API 均不在检测范围内；2xx 不代表完整页面或功能正常。

403、身份验证挑战、跳转、超时及 DNS/TLS 错误需按各自原因排查，不能单凭这些结果判断校园网掉线。

每轮结果在内存中保留当次连接策略和详情，修改设置不改变已有结果。具体网址不进入检测历史或诊断导出。

检测历史不保存当次网址策略；诊断摘要显示的当前设置不能作为历史路径证据。通过比例按基础联网可用的检测次数计算，不包含常用网址结果，也不代表校园链路持续在线率或真实带宽。

| 连接选项 | 请求方式 |
| --- | --- |
| 使用系统设置 | 使用适用的系统代理、自动代理规则（PAC）及例外规则；实际是否走代理取决于对应规则，选项本身不说明具体节点 |
| 绕过系统代理 | 绕过系统 HTTP/HTTPS 代理配置，仍使用系统 DNS 和路由 |

macOS 通过 URLSession 使用系统配置，Windows 由 WinHTTP 的自动代理模式读取适用配置。浏览器可能另有扩展或独立代理、缓存、登录 Cookie、DNS／IPv4／IPv6 路径及页面脚本使用的 API，结果可能不同。

VPN/TUN 的全局路由、按应用或目的地址分流可能改变检测路径；IPv4／IPv6、DNS／Fake-IP、代理节点及隧道重连也可能影响结果。隧道存在、网址有响应和需要校园认证分别判断，不能单凭其中一项定位故障或节点。

## 系统配置

应用读取网络及代理状态，提供诊断和可复制的建议规则，不直接修改系统 VPN、代理、DNS 或路由。读取失败时显示“未知”。

两端的复制摘要与 JSON 报告共用当前匿名快照，包括连接类型、系统代理、TUN 和自动重连保护。仅导出固定状态及有界的冷却秒数，不含网卡或认证范围标识；环境更新期间不把旧连接和核验结果标为当前。导出不发请求、不改调度，历史采样仍单独列出。此扩展为可选字段，保持报告格式版本 1。

新检测明细保留实际完成时间、基础项耗时及本轮开始时的匿名上下文；未等待的项目不填零，完整检测中单项失败也保留。检测明细限最近 24 小时、最多 360 次，操作事件最多 300 条。连接、核验或记住网络失败时可另存本轮故障现场，后续成功只追加记录，不覆盖原失败；取消和失效轮次不拼接新网络的状态。旧记录缺少的可选字段不补写。

这些记录只用于诊断，不授信、不改变网络记忆、不解除保护或缩短冷却。文本摘要最多列出最近三次异常。macOS 在用户选定保存位置后固定报告快照并后台保存，不扫描系统崩溃日志；只读与预览模式也不访问系统崩溃来源。

两端的[校园直连设置](PROXY-DIRECT.md)可按用户选择修改 Clash Verge Rev 扩展脚本、独立 Mihomo YAML 或 sing-box JSON 配置。先预览固定改动摘要，再加密备份并保存；不导入其他订阅，不调用客户端私有重载接口。保存后须在代理客户端重新应用配置。

规则只针对固定校园域名和宿舍认证地址，必要时保留原 DNS 设置并补充真实地址解析及单地址 TUN 例外。它不改变校园服务核验、网络资格或认证次数；也不能解决所有 TUN 故障。客户端管理的订阅和临时运行配置可能被重新生成，不作为独立配置自动修改。

排查时先看结果中所用的连接方式及错误，再核对分流、节点和 DNS，并在浏览器验证所需功能。校园登录只处理校园认证，代理或网站问题需另行处理。

## 实现与参考

macOS 合并同一同步代码段内重复的完整物理租约采集。异步前后、物理 DNS／套接字绑定及 HTTP 发送前仍重新核验，不以时间缓存替代发送前检查。

Windows 对固定域名的加密解析设置有界任务队列，超时或取消后停止等待，丢弃迟到结果。已有合格 HTTPS 旧候选时，保留回退所需预算，避免底层查询清理拖过整轮截止时间。连接建立、发送前和结果返回时仍核验物理绑定及证书；认证提交不进入该队列。

Windows 登录准备阶段失败后，重试等待期间检查两项基础结果，保留原截止时间；单项快速成功不会打断已确认的恢复流程。仅快速检测成功后需要补充完整检测时，才安排只读补检；不会用补检取代已到期的登录准备重试。

- [URLSession 代理](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/connectionproxydictionary)：未覆盖代理配置时采用系统设置。
- [Apple VPN 路由](https://developer.apple.com/documentation/networkextension/routing-your-vpn-network-traffic)：路由、全量隧道和按应用规则可改变连接路径。
- [WinHTTP 代理](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpopen)：自动代理模式采用适用的系统和用户配置。
- [Chrome 代理](https://developer.chrome.com/docs/extensions/reference/api/proxy)：扩展可使用系统、PAC、固定代理或直连设置。
