# 平台差异

macOS 与 Windows 都支持联网检测、校园登录、自动重连、网络记忆和校园直连设置。日常使用按[教程](USER-GUIDE.md)操作，主要差异如下。

| 项目 | macOS | Windows |
| --- | --- | --- |
| 系统要求 | macOS 14+，Apple 芯片或 Intel | Windows 11 x64 |
| 关窗后运行位置 | 菜单栏 | 系统托盘 |
| 账号和密码 | 保存在系统钥匙串 | 保存在 Windows 凭据管理器 |
| 登录时启动 | 在设置中开启“登录时打开” | 在设置中开启“开机启动” |
| 自动找回 Wi-Fi | 找回已记住并选定、无需无线密码的校园 Wi-Fi | 还可使用所选 Wi-Fi 已保存的系统连接，不读取无线密码 |
| 排查报告 | 包含匿名故障记录，不收集系统崩溃日志 | 还可按需附本程序的系统崩溃元数据 |
| 安装与卸载 | DMG 拖入“应用程序”；在应用内卸载 | 运行 EXE 安装；在应用内或系统设置中卸载 |

自动找网都受系统权限和硬件限制，已有 Wi-Fi、热点或网线连接时不会切换网络。两端升级均保留数据，卸载默认保留账号和本机数据。[安装、升级与卸载](INSTALLATION.md)

开着代理时校园网异常，可查看[校园直连设置](PROXY-DIRECT.md)。按客户端步骤操作即可；需要修改配置文件时，先预览确认，应用会加密备份并提供撤销。保存后仍须在代理软件重新应用，不会代为修改系统 VPN、代理、DNS 或路由。

<details>
<summary>网络检测与界面的技术差异</summary>

| 项目 | macOS | Windows |
| --- | --- | --- |
| 界面与辅助功能 | SwiftUI 桌面窗口及辅助标签 | Win32／Direct2D，UI Automation 提供者 |
| HTTP 传输 | 固定认证物理通道与 URLSession 网址检测 | 固定认证物理通道使用 libcurl／Schannel，普通网址使用 WinHTTP |
| 受限备用解析 | 关联网卡解析失败后，为三个固定域名尝试绑定出口的 HTTPS 解析 | 提供受限 HTTPS 解析，使用原生物理通道 |
| 报告保存 | 选定保存位置后固定内容，在后台保存 | 按当前诊断导出，可附有限的崩溃元数据 |

两端分别检测当前上网方式与校园直连，独立显示校园服务核验。优先观察可靠的系统主物理连接；新网线不继承 Wi-Fi 的资格，凭据操作保持原有效出口。权限、系统代理和网卡信息因平台而异；无法读取时显示“未知”，不据此判断校园身份。

两端支持换网优先恢复、网址补查及有限次数的 DNS 重试。普通网站故障只更新诊断，不因此提交校园认证。校园直连设置只处理本人选定并确认的文件，客户端需重新应用。

账号、网址和许可均支持收纳。macOS 按账号草稿状态保留编辑区；Windows 提供对应分组收纳。检测详情显示实际结果及所用设置。

</details>

<details>
<summary>原生验证与 Windows 测试模式</summary>

Windows 可移植核心用于跨平台规则检查，mock SDK 用于语法检查；原生构建、界面和设备行为须在对应平台验证。

Windows 的构建脚本包含核心测试、隔离窗口自检和打包校验，公开下载只提供 EXE。另提供两种不能同时启用的测试模式：

- `--observe-only`：检测真实网络，不写正式数据或提交校园认证。
- `--offline-smoke`：使用假服务，检查后自动退出。

参数及回执见[Windows 构建](../BUILD-WINDOWS.md)；校园网、Wi-Fi 开关及权限检查见[Windows 实机测试](../WINDOWS-TESTING.md)。

</details>
